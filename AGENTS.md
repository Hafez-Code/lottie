# Project instructions

## Version records

For every future batch of project changes, create a separate Markdown record in `versions/` using the next sequential filename `vNNN-YYYY-MM-DD.md`. Use the user's local date. These record numbers are separate from the application version in `package.json`.

Describe what was actually added, changed, or fixed, list affected files, and state validation results and remaining limitations. Update the current batch's record as work proceeds. Never present planned work or pre-existing workspace changes as completed work in the new batch.

Add a link to each new record in `versions/README.md`. Preserve previous records. Documentation-only changes also require a record. Do not bump the application version unless the task requires it.
