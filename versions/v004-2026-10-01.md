# v004 — دمج التحقق متعدد الفريمات وفحص المشاهد

التاريخ: 2026-10-01.

## المنفذ

- دمج حساب تخطيط contact sheets من diffusionstudio/editor عند commit f1f6d87862e50b9a79dafd9247e5b17c58a2a1a0، مع حفظ MPL-2.0 والمصدر وإدراجهما في إعدادات حزمة Electron.
- ربط التخطيط بمحرك Lottie الحالي لتكوين صورة PNG معنونة لعدة فريمات؛ لم يتغير تصميم التطبيق أو محرّك المشاهد.
- إضافة MCP capture_scene_frames لالتقاط 1–12 فريمًا، تلقائيًا البداية والوسط والنهاية، مع نتائج منظمة وصورة مدمجة. إضافة endpoint محلي /api/chat/capture-frames.
- حفظ كل لقطة في مسار مستقل تحت .studio/captures بدل الاعتماد على ملف واحد يتغير.
- إضافة check_scene لفحص بيانات Lottie، توقيت الطبقات والشفافية الثابتة ومراجع precomp والدورات المرجعية، مع إحصاءات وقيود واضحة.
- توجيه agents لاستخدام اللقطات الجديدة، وإتاحة الأدوات لمسار Claude الحالي. مسار API يراجع صورة الفريمات بعد حفظ النتيجة بدل فريم البداية وحده.
- إضافة CLI scenes capture وscenes check يستخدمان أدوات MCP نفسها؛ إصلاح ترتيب تعريف help عند استخدامه.
- إضافة اختبارات لتخطيط الصور والالتقاط وحفظ اللقطات والفحص البنيوي ونتائج MCP ومراجعة API.

## القيود

لم تُدمج حزمة agent-chat أو محرّك الفيديو JSX؛ يستمر ربط agents الحالي. الفحص بنيوي واللقطات عينات، ولا يثبتان كامل الحركة أو الصوت. لم تُختبر مكالمات AI مدفوعة أو حزمة تثبيت جديدة.

طلب المستخدم تنفيذ مهمة بواسطة ollama launch claude --model deepseek-v4.1-flash:cloud. حاولنا تكليفه بإضافة اختبارات مستقلة ومراجعة الدمج دون تعديل الملفات الموجودة. رفضت مراجعة الموافقات التلقائية التشغيل بسبب احتمال إرسال محتوى المستودع إلى مزود سحابي دون موافقة صريحة على هذا المحتوى؛ لم يعمل الوكيل ولم يُنسب إليه أي تنفيذ. التشغيل معلق حتى موافقة المستخدم على الإرسال.
