# v002 — ربط الشات بالـ AI ومساحة المشاهد

التاريخ: 2026-10-01

## الإضافات

- شات داخل مساحة المشهد، مع حفظ المحادثة والطلبات والمرفقات بجانب المشهد داخل `.studio`.
- تشغيل Codex وClaude Code وOpenCode من الشات، ومتابعة الرد والحالة، مع الإيقاف وإعادة المحاولة والتعامل مع انقطاع التطبيق.
- اكتشاف البرامج التنفيذية في PATH ومواقع تثبيت إضافية، والتمييز بين وجود CLI ووجود إعدادات فقط. اكتشاف البرنامج لا يثبت تسجيل الدخول.
- مسار OpenAI API بمفتاح واسم نموذج يحددهما المستخدم. في Electron يُحفظ المفتاح مشفرًا باستخدام `safeStorage`؛ وفي Vite يبقى في ذاكرة السيرفر فقط.
- التحقق من بنية JSON الناتج قبل استبدال المشهد في مسار API، وحفظ النسخة السابقة في `.studio/before-api.json`.
- استقبال صور وGIF وSVG وفيديو في الرئيسية والشات. استخراج ٣ فريمات من الفيديو، وصورة ثابتة من GIF/SVG/AVIF للاستخدام البصري. الأصل يظل محفوظًا.
- حد المرفقات: ٤ ملفات، ٨ MB للملف، و٢٤ MB إجمالًا قبل استخراج الفريمات.
- اختيار مجلد مشاريع من النظام في Electron وحفظه بين مرات التشغيل. المجلد يحتوي مجلدات المشاريع، وكل مشروع يحتوي مجلدات المشاهد.
- تخزين المشاريع الافتراضية في مجلد بيانات المستخدم عند تشغيل النسخة المثبتة، وتقديم الملفات والمشاهد من المجلد المختار.
- شاشة بدء فيها اللوجو وحالة تحميل المشاريع، مع إعادة المحاولة عند الفشل.
- Inspect بالنقر على المعاينة أو باختيار طبقة من القائمة، وإرسال الطبقة والفريم مع الطلب التالي.
- التقاط PNG للفريم من CanvasKit؛ وأداة `capture_scene` عبر MCP لقراءة أحدث مصدر محفوظ. إعداد MCP مؤقت لكل تشغيل Codex وClaude Code دون تعديل إعداداتهما العامة.
- مراجعة بصرية لفريم مولد في مسار OpenAI API عندما تكون المعاينة مفتوحة؛ تُعرض القيود أو فشل المراجعة دون ادعاء تحقق ناجح.

## الإصلاحات والتغييرات

- الطلب الجديد بدون اختيار مشروع ينشئ مشروعًا جديدًا بدل إضافته لأول مشروع سابق.
- انتظار تحديث قائمة المشاهد قبل الانتقال للمشهد المنشأ.
- تنظيم الشات والمعاينة والمشاهد والخصائص، وضبط ملاءمة المعاينة للمساحة المتبقية بين اللوحات.
- ربط إنشاء وحفظ وحذف المشاهد في Electron بمسارات السيرفر الفعلية، وتحديث المشهد بعد انتهاء تشغيل الـ agent.
- منع الطلبات من صفحات خارجية من تشغيل الشات، وتقييد مسارات المشاهد، وتشغيل CLI بدون shell.
- تفعيل `skipLibCheck` لتجاوز أخطاء تعريفات Kobalte الموجودة في dependencies، مع استمرار الفحص الصارم لكود التطبيق.
- إضافة `PRODUCT.md` و`DESIGN.md` لتوثيق رحلة المنتج والتصميم الحالي الذي اختاره المستخدم.

## التحقق والقيود

- `npm run build`: نجح. تحذيرات Vite الخاصة بوحدات fs/path في CanvasKit لا تمنع البناء.
- `npm run check:workflow`: نجحت ١٣ حالة لاختبار التشغيل والحفظ والفشل والإلغاء وإعادة المحاولة والمرفقات ومسار API وقراءة ردود الأدوات الثلاث.
- `npm run check:text-slots`: نجحت ٣ حالات Unicode الموجودة.
- فحص صياغة ملفات Electron، ومراجعة الواجهة في المتصفح، وتحديد طبقة بالنقر على المعاينة: نجحت.
- طلب معاينة فعلية للفريم ١٥ عبر الواجهة المحلية: عاد ملف PNG صالح من CanvasKit.
- تجهيز فيديو MP4 تجريبي من الواجهة: نجح وظهر المرفق بعد انتهاء استخراج الفريمات.
- لم يتم تنفيذ طلب AI مدفوع أو تجربة حساب حقيقي. اختبارات تشغيل agents وAPI تستخدم عمليات وردودًا وهمية؛ تسجيل الدخول وصلاحيات الأدوات وقبول النموذج للمرفقات تحتاج تجربة بحساب المستخدم.
- اختيار المجلد والتشفير موجودان في Electron، لكن لم يُختبرا في تطبيق macOS مثبت في هذه الدفعة.
- Inspect يختار الطبقات الرئيسية فقط، وليس العناصر الداخلية في precompositions. للمشاهد ذات track mattes أو أكثر من ١٠٠ طبقة تُستخدم القائمة بدل النقر.
- مراجعة فريم واحد في مسار API لا تثبت صحة الحركة أو التوقيت عبر كامل الأنيميشن.
- المرفقات لا تتضمن تحليلًا صوتيًا، وGIF يُقدم بصريًا كصورة ثابتة مع حفظ الملف الأصلي.
- لم يتغير رقم إصدار التطبيق في `package.json`. التعديلات الموجودة قبل هذه الدفعة ليست إضافات تُنسب إلى هذا السجل.
